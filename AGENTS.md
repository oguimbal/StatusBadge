# Status Badge

Application macOS Rust/GPUI. Domaine pur et protocole dans `statusbadge-core`, vues et géométrie dans `statusbadge-ui`, accès système/réseau dans `statusbadge`. GPUI épinglé comme AgentsMon.

L’application ne contient aucune URL de sudo : tout sudo est ajouté par l’utilisateur et implémente `docs/protocol.md`. Seule adresse codée : le dépôt GitHub des mises à jour (`REPOSITORY`, `crates/statusbadge-core/src/updates.rs`). Toute évolution du protocole se fait dans ce document d’abord, de façon compatible avec les sudos déjà déployés. Ce dépôt est public : aucun nom de projet, domaine ou URL de sudo réel dans le code, les tests, les exemples ou la documentation (exemples en `*.example`, noms fictifs).

Avant de terminer : `cargo fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `python3 -m unittest discover -s scripts -p 'test_*.py'`. Compiler avec `cargo mini`. Vérifier aussi le rendu (`--demo`), le drag et le menu natifs.

Jetons uniquement dans le Trousseau ; aucun bearer ni lien de retour dans les logs. Ne pas suivre les redirections authentifiées. Un sudo est indépendant des autres. Un 401/403 déconnecte, une panne réseau ne déconnecte pas. Un jeton n’est enregistré qu’après une première réponse valide du résumé.

Release (même schéma qu’AgentsMon, décidé le 12/11/2026) : `./release.sh` lance les vérifications, incrémente la version, committe, tague et pousse vers le remote GitHub ; il ne construit rien. Le tag `v*` lance `.github/workflows/release.yml` (`macos-latest`) : build universel, signature Developer ID avec runtime renforcé, notarisation et agrafage du `.app` puis du DMG, publication de `StatusBadge.dmg` dans la release GitHub. `workflow_dispatch` fait la même chose sans publier (DMG en artefact du run) : à lancer avant de taguer après toute modification du workflow ou de `bundle/`. Secrets du dépôt : `CODESIGN_CERT_P12_BASE64`, `CODESIGN_CERT_PASSWORD`, `NOTARY_APPLE_ID`, `NOTARY_TEAM_ID`, `NOTARY_PASSWORD` ; un secret absent fait échouer le job, jamais de build public non signé. Le nom de l’identité de signature est public (`bundle/release-config.sh`).

Mises à jour : `updater.rs` lit `releases/latest` du dépôt `REPOSITORY` sur l’API GitHub au lancement puis toutes les 24 heures (30 minutes après un échec), sans jeton. Pas de serveur ni de manifeste. La lecture de la release est dans `statusbadge-core` : version supérieure, ni brouillon ni préversion, fichier `StatusBadge.dmg` à l’adresse exacte de ce dépôt, taille et empreinte SHA-256 (`digest`) fournies par GitHub. Le téléchargement suit les redirections de GitHub (requête sans identifiant), puis taille, SHA-256 et Gatekeeper (`spctl`) sont vérifiés avant d’ouvrir le DMG. Le nom `StatusBadge.dmg` et l’orthographe exacte du dépôt ne changent pas : les versions installées en dépendent. Quand le bundle installé est remplacé par une version supérieure, le badge redémarre dessus (attente de la fin du processus, à cause du verrou d’instance unique). `--demo` ne fait aucune requête.

Textes factuels en français. Pulsation rouge lente, sans mouvement, compatible avec Réduire les animations.
